# LocalProject 页面与功能清单

状态：首版功能基线（已实现，持续维护）

视觉方向：第二套「深色开发者工作台」

目标平台：macOS，Electron + Vue

对应 CLI：`local-project-cli` / 全局命令 `project`

## 1. 文档目的

本文档是 Desktop 首版的页面、功能和验收基线，用来解决以下问题：

- 开始编码前确定页面边界，避免边做边增加页面。
- 将现有 CLI 的真实能力映射到 Desktop，避免功能遗漏。
- 区分页面、面板、抽屉和确认弹窗，避免把列表与操作混在同一选择菜单中。
- 明确 CLI 与 Desktop 的共用能力、独立能力和更新边界。
- 为后续实现、测试和人工验收提供逐项可勾选的清单。

本文档记录首版产品范围和验收基线；实际可用命令、构建方式和发布边界以 README、自动化测试及当前源码为准。

## 2. 产品与导航模型

### 2.1 核心数据关系

```text
Project
└── Repository
    ├── Local path / optional openTarget
    ├── Git state
    └── Optional explicit default opener
```

Desktop 与 CLI 读取同一个注册表：

```text
~/.local-project-cli/registry.json
```

注册表路径仍遵循：显式指定 > `LOCAL_PROJECT_CLI_REGISTRY` > 默认路径。Desktop 首版默认读取标准路径；自定义路径在设置页中选择，不覆盖 npm CLI 的安装或更新状态。

### 2.2 一级导航

一级导航固定为五项：

1. 概览
2. 项目
3. 未推送
4. 打开工具
5. 设置

“项目详情”是“项目”下的独立路由；“代码库详情”使用项目详情页中的选中态和右侧检查器，不再增加一级导航。

### 2.3 页面总表

| 编号 | 页面 | 建议路由 | 核心职责 |
| --- | --- | --- | --- |
| P0 | 启动与首次使用状态 | 应用启动阶段 | 加载注册表、校验 Schema、处理空数据和错误 |
| P1 | 概览 | `/overview` | 汇总本机项目与 Git 状态，快速进入待处理工作 |
| P2 | 项目列表 | `/projects` | 浏览、搜索、新增项目，进入项目详情 |
| P3 | 项目详情 | `/projects/:projectId` | 管理一个项目及其代码库，查看选中代码库详情并执行操作 |
| P4 | 未推送 | `/pending` | 区分可安全推送与需人工处理的代码库，支持单个和批量安全推送 |
| P5 | 打开工具 | `/openers` | 独立展示 opener 列表，并通过详情、抽屉和弹窗管理 opener |
| P6 | 设置 | `/settings` | 展示注册表、默认 opener、版本与兼容信息 |

首版共 7 个页面/启动状态，其中用户日常使用的一级页面为 5 个。

## 3. 全局应用框架

所有一级页面共享以下框架能力。

### 3.1 窗口与导航

- macOS 原生窗口标题栏与交通灯区域。
- 左侧固定导航，当前页面有明确选中态。
- “未推送”导航项显示代码库数量角标，不显示提交总数。
- 页面切换立即发生，不等待全量 Git 扫描完成。
- 恢复上次打开的一级页面；若目标实体已删除，则回到概览。

### 3.2 非阻塞 Git 扫描

- 先读取并展示注册表中的项目与代码库结构，再异步读取 Git 状态。
- 全局状态显示“正在获取 Git 状态…”，同时显示已完成数量，例如 `18/32`。
- 每个代码库独立更新，不等待所有代码库完成后一次性展示。
- 默认并发数沿用现有扫描器的 6 个任务上限。
- 单个代码库读取失败不会中断其他代码库；该行显示错误状态和“重试”。
- 页面切换复用当前扫描结果，不因每次切换都重新全量扫描。
- 用户可手动刷新本地状态；远端 `fetch --prune` 是单独、明确的操作。
- 扫描状态至少覆盖：等待、读取中、成功、部分失败、全部完成。
- 所有滚动区域使用透明轨道，仅显示细滚动滑块，避免系统轨道背景破坏深色界面。

### 3.3 全局通知与危险操作

- 成功、失败和警告使用非阻塞通知，不通过页面跳转展示结果。
- 删除项目、删除代码库索引、删除 opener、执行 Push 必须确认。
- “删除项目/代码库”只删除注册表索引，明确提示“不删除磁盘文件”。
- Push 失败需要保留失败原因和可重试入口。
- 所有写入注册表的操作都需要检测外部变更，避免 CLI 与 Desktop 相互覆盖。

## 4. P0 启动与首次使用状态

P0 不是一级导航页，但属于必须实现的完整使用流程。

### 4.1 正常启动

- 读取注册表路径。
- 注册表不存在时创建默认注册表和内置 opener。
- 校验 `schemaVersion`、项目、代码库、opener 和默认 opener 引用。
- 先进入上次页面，再后台启动 Git 状态扫描。

### 4.2 首次使用空态

- 说明 LocalProject 与 CLI 共用本机配置。
- 主操作：“添加第一个项目”。
- 次操作：“打开注册表所在位置”。
- 不要求先安装 npm CLI；Desktop 内置共享 core。
- 不创建示例项目，不写入机器相关 opener。

### 4.3 注册表异常

- JSON 无法解析：停止写入，显示文件路径和错误摘要。
- Schema 版本过新：只读保护，不尝试降级覆盖。
- 可迁移旧版本：迁移前备份，再执行迁移并记录结果。
- 默认 opener 或引用失效：提示修复，不静默删除用户配置。
- 提供“在 Finder 中显示”“复制路径”和“重试读取”。

## 5. P1 概览

### 5.1 页面目标

用一屏回答：本机登记了什么、哪些代码库需要处理、下一步去哪里。

### 5.2 内容区

- 项目总数。
- 代码库总数。
- 有未提交修改的代码库数量。
- 有未推送提交的代码库数量。
- 需要人工处理的代码库列表。
- 最近扫描时间和当前扫描进度。

“需要处理”使用有最大宽度的小卡片和流式布局，按窗口宽度自动换行，避免少量字段占满整行。标题和卡片流直接置于页面内容区，不再套占满整行的外层卡片。状态文案必须写清对象和方向，例如“落后远端 7 个提交”“2 个文件修改未提交”“2 个提交未推送”，不使用“落后 7”“2 个修改”等省略表达。

“需要人工处理”包括：

- 非 Git 目录。
- Git 状态读取失败。
- 有未提交修改。
- 落后远端。
- 未设置上游分支（upstream）。
- detached HEAD。
- 正在 merge、rebase 或 cherry-pick。

### 5.3 页面操作

- 点击统计项进入对应筛选结果。
- 点击代码库进入所属项目详情并选中该代码库。
- 手动刷新本地 Git 状态。
- 明确执行“获取远端状态”，触发 `fetch --prune` 后刷新。
- 添加项目。

### 5.4 页面状态

- 无项目：显示首次使用引导。
- 有项目但无代码库：引导进入项目并添加代码库。
- 扫描中：先显示注册表统计，Git 相关数字显示加载态并渐进更新。
- 全部正常：显示“当前无需处理”。
- 部分失败：保留成功数据，并显示失败数量。

## 6. P2 项目列表

### 6.1 页面目标

只负责浏览和选择项目，不在列表项中混入编辑、删除等操作菜单。

### 6.2 列表信息

- 项目名称。
- 代码库数量。
- 有未提交修改的代码库数量。
- 有未推送提交的代码库数量。
- 项目级扫描状态。
- 可选的 `workspacePath`，只在详情中展示，不挤占主列表。

### 6.3 页面操作

- 按项目名称搜索。
- 点击项目进入项目详情。
- 添加项目。
- 手动刷新项目统计。

### 6.4 新增项目弹窗

字段：

- 项目名称，必填。
- Workspace 路径，选填，对应现有 `workspacePath`。

校验：

- 名称不能为空。
- Project slug 全局唯一。
- 重复时保留用户输入并显示原因。

项目列表栏提供重命名入口；只更新注册表中的名称和 slug，不改变项目 id、代码库归属或磁盘目录。

### 6.5 页面状态

- 空列表。
- 搜索无结果。
- 项目统计扫描中。
- 部分代码库读取失败。

## 7. P3 项目详情

### 7.1 页面布局

延续已选择的第二套深色工作台方向：

- 左侧：一级导航。
- 中间第一栏：项目列表，用于切换和新增项目。
- 中间第二栏：当前项目的代码库列表；“添加代码库”作为高频操作放在列表标题右侧。
- 项目与代码库列表左侧使用名称首字头像：中文取首个汉字，英文取大写首字母；不使用缺少区分度的通用文件夹或电脑图标。
- 主内容区：选中代码库的完整 Git 信息与操作。
- 窄窗口时，代码库列表可收起；详情仍是主任务。

### 7.2 项目信息

- 项目名称。
- 项目下代码库数量。
- `workspacePath`（如存在）。
- 从代码库列表标题右侧添加代码库。
- 当前项目标题右侧使用“更多操作”菜单，集中放置修改项目名称和移除项目索引；移除时再次确认受影响的代码库数量。

### 7.3 代码库列表

每行显示：

- 代码库名称。
- 当前分支。
- 关键 Git 状态：修改数、未推送数、落后数或异常原因。
- 扫描中或读取失败状态。
- 当前选中态。

列表行只负责选择代码库；打开、Push、删除等动作统一放在详情区，避免列表与操作混在一起。

### 7.4 新增代码库抽屉

字段：

- 代码库目录，必填，使用系统目录选择器。
- 代码库名称，必填，默认取目录名。
- 首次使用的 opener，选填。
- `openTarget`，选填；相对路径以代码库目录为基准。

校验：

- 路径存在且可读。
- 同一个规范化物理路径不能重复登记。
- 同一项目内 Repository slug 唯一。
- 非 Git 目录允许登记，并明确标记“未初始化 Git”。

### 7.5 代码库详情信息

基础信息：

- 名称和物理路径。
- 实际打开目标：`openTarget` 或代码库路径。
- 上次成功使用的 opener。

Git 信息：

- 状态摘要按“本地 / 远程”两行对照展示。
- 本地行包含当前本地分支，以及可同时存在的未提交文件数、未推送提交数、未拉取提交数、Git 操作中、detached HEAD 和未设置上游分支等状态。
- 远程行包含 upstream 分支，以及该远程跟踪分支最后一次提交的摘要、提交人、时间和 hash。远程信息基于本地保存的远程跟踪引用；执行“获取远端状态”后通过 fetch 更新。
- “安全推送”位于本地状态行；“安全拉取”位于远程状态行，使信息和对应 Git 操作保持同一区域。
- ahead / behind 数量。
- detached HEAD。
- merge / rebase / cherry-pick 状态。
- Git 内容分组统一使用同一套样式，并严格按“未提交的文件 → 未推送的提交 → 未拉取的远端提交 → 最近提交”排序，避免把工作区文件误解为某次提交所修改的文件。
- 未提交的文件仅在有数据时展示，包含状态码和路径；默认展示前 10 条，超过 10 条时折叠剩余内容，并提供手动展开和收起入口。
- 未推送的提交仅在有数据时展示，包含 hash 和摘要；默认展示前 10 条，超过 10 条时折叠剩余内容，并提供手动展开和收起入口。
- 未拉取的远端提交仅在 behind 大于 0 时展示，包含 hash、摘要、提交人和时间；默认展示前 10 条，超过 10 条时折叠剩余内容，并提供手动展开和收起入口。数据来自本地 upstream 跟踪引用，执行 fetch 后更新，整个分组使用危险红色系。
- Git 状态颜色在所有页面统一：未提交的文件使用危险红色，未推送的提交使用警告黄色，状态正常使用成功绿色；同一状态的标题、数量、标签、概览指标和代码库状态点复用同一全局色值。
- 最近提交固定放在最后，展示最近 5 条的 hash、时间、提交人和摘要，不提供展开入口；没有提交时展示空状态。
- 文件路径使用 Git NUL 分隔输出解析，必须正确展示中文、空格和重命名路径，不显示八进制转义文本。
- 非 Git 状态。
- Git 读取错误。

### 7.6 代码库详情操作

主操作：

- 使用当前 opener 打开，例如“使用 VS Code 打开”。

底部操作区固定在详情面板底部，不随 Git 内容列表滚动，只保留默认 opener、选择其他工具和 Finder 等打开相关操作。主按钮使用较宽的固定宽度，次按钮使用统一固定宽度；紧凑窗口使用更窄的一组固定宽度，不压缩按钮文字。

Desktop 采用常驻小工具密度：默认窗口约 1240 × 820，允许缩小到 980 × 640；主菜单、项目栏和代码库栏使用紧凑宽度，列表行、字号与详情间距同步收紧。代码库栏不再保留底部工具条；主导航也不常驻显示“已连接”和 Schema 等低频诊断信息，异常通过 Toast 和页面错误状态提示，Schema 版本保留在设置页。

整体主题采用黑、白、灰中性色，不使用蓝色作为品牌色或交互强调色；主按钮、选中态、链接、分支、焦点框和代码文本均使用灰白层级。红色、黄色和绿色仅保留给 Git 风险、待同步和正常状态等已经定义的语义反馈。

次操作：

- 代码库标题右侧直接提供刷新本地 Git 状态、获取远端状态和复制代码库地址三个高频快捷操作；复制成功后显示明确的成功提示。
- 修改代码库名称属于低频操作，收进代码库标题右侧的“更多操作”；该菜单只包含代码库级操作，不混入项目级操作。
- 选择其他工具打开只影响本次操作，不写入代码库默认值。
- 代码库默认打开工具必须从代码库“更多操作”中显式设置，写入 `defaultOpenerId`；也可以清除并跟随全局默认。
- “选择打开工具”使用加宽弹窗和固定宽度卡片网格，支持一行展示 4 个 opener，避免单列横条占用过多纵向空间。
- 打开工具管理页的列表行整体可点击，不显示无额外含义的右箭头；新增入口只保留在列表标题右侧，不在列表底部重复展示。
- 查看 Git 详情；展开完整的未提交文件和未推送提交。
- 安全推送。
- 在 Finder 中显示。
- 复制代码库路径。
- 刷新本地 Git 状态。
- 获取远端状态并刷新。
- 从索引移除代码库。

### 7.7 安全推送规则

满足以下全部条件才可推送：

- 是 Git 工作区。
- 不是 detached HEAD。
- 没有进行 merge、rebase 或 cherry-pick。
- 已设置 upstream。
- ahead 大于 0。
- behind 等于 0。

有未提交修改不阻止 Push，但确认弹窗必须说明：“本次只推送已有提交，不包含未提交文件”。

不可推送时禁用操作并展示准确原因，不能只显示笼统的“失败”。

### 7.8 移除确认

- 显示项目名、代码库名和物理路径。
- 明确“只从索引移除，不删除磁盘文件”。
- 完成后返回当前项目；若项目已无代码库，显示项目空态。

代码库详情提供重命名入口；只更新注册表中的名称和 slug，不重命名磁盘目录。首版仍不提供跨项目移动或修改路径。

## 8. P4 未推送

### 8.1 页面目标

集中完成“今天可以安全收尾的 Push”，同时把不能自动处理的情况清晰分离。

### 8.2 分组

#### 可安全推送

- 满足全部安全推送规则。
- 显示项目、代码库、分支、未推送数量和最新提交摘要。
- 有多个提交时显示“最新摘要 · 另有 N 条”。

#### 需要人工处理

- 有未推送提交，但因 behind、无 upstream、detached HEAD 或 Git 操作中而不可推送。
- 说明精确原因。
- 点击进入代码库详情，不在 Desktop 内自动 rebase、merge 或设置 upstream。

单纯有未提交修改、但没有未推送提交的代码库属于概览的“需要处理”，不进入“未推送”主列表。

### 8.3 页面操作

- 打开代码库详情。
- 使用默认或上次 opener 打开。
- 单个安全推送。
- 批量推送全部符合安全条件的代码库。
- 刷新本地状态。
- 获取远端状态后重新评估。

### 8.4 批量推送确认弹窗

弹窗分成两个独立列表：

- 将推送：项目/代码库、提交数量、upstream。
- 将跳过：项目/代码库、跳过原因。

确认后逐个执行，展示每项进度和结果。单个失败不阻断后续项目，最终汇总成功、失败和跳过数量。

### 8.5 页面状态

- 扫描中，列表渐进更新。
- 暂无未推送代码库。
- 全部可安全推送。
- 部分需要人工处理。
- 推送进行中，禁用重复提交。
- 推送部分失败，可重试失败项。

## 9. P5 打开工具

### 9.1 页面目标

把“列表”和“操作”明确分开。主页面展示 opener 列表和详情；新增、编辑使用抽屉；删除使用确认弹窗。

### 9.2 列表信息

- 显示名称。
- 稳定 id。
- 启动方式：macOS 应用、后台命令、终端命令。
- 是否为默认 opener。
- 被多少个代码库显式设为默认。

### 9.3 详情区

- id，只读。
- 显示名称。
- `command`。
- `args`。
- 解析后的启动方式。
- 默认状态。
- 引用该 opener 的代码库列表。

详情区操作：

- 编辑。
- 设为默认。
- 删除。

### 9.4 新增/编辑 opener 抽屉

三种启动方式：

#### macOS 应用

- id。
- 显示名称。
- 应用名称或 `.app` 完整路径。
- 自动生成 `open -a <application> {path}`。

#### 后台命令

- id。
- 显示名称。
- `command`。
- `args` 字符串数组。
- 默认参数为 `['{path}']`。

#### 终端命令

- id。
- 显示名称。
- `command`。
- `args` 字符串数组。
- 通过 macOS Terminal 交互运行。

共同校验：

- id 只能包含字母、数字、点、下划线和连字符。
- id 新增后不可修改。
- 名称和 command 不能为空。
- args 至少包含一个字符串。
- `{path}` 是路径替换标记；缺失时给出警告，但不强制禁止高级用法。
- 编辑时保留原始 command/args，不把自定义命令错误简化为“应用路径”。

### 9.5 删除规则

- 默认 opener 不能删除，必须先设置其他默认值。
- 被任何 `Repository.defaultOpenerId` 引用的 opener 不能删除。
- 删除失败时列出引用它的项目/代码库，提供跳转入口。
- 删除只修改注册表，不卸载本机软件。

### 9.6 内置 opener

首次创建注册表时包含：

- Visual Studio Code
- PhpStorm
- Xcode
- 微信开发者工具
- Android Studio
- Finder

内置项只使用通用名称，不内置用户机器上的版本化路径，例如 `Android Studio 2.app`。用户通过自定义 opener 添加机器特定配置。

## 13. 状态覆盖矩阵

### 13.1 Git 状态

| 状态 | 列表展示 | 详情展示 | 可安全 Push |
| --- | --- | --- | --- |
| 已同步 | 绿色状态 | 分支、upstream、最后提交 | 否，无未推送提交 |
| 有未提交修改 | 修改数量 | 文件状态码和路径 | 视其他条件而定 |
| 有未推送提交 | ahead 数量 | 提交 hash 和摘要 | 是，若无其他阻断 |
| 落后远端 | behind 数量 | upstream 和落后原因 | 否 |
| 无 upstream | 明确文字 | 提示需要人工设置 | 否 |
| detached HEAD | 明确文字 | 当前 oid | 否 |
| merge/rebase/cherry-pick | 操作中 | 操作类型 | 否 |
| 非 Git 目录 | 未初始化 Git | 路径和说明 | 否 |
| 读取失败 | 错误标记 | 错误摘要和重试 | 否 |
| 扫描中 | 骨架或进度 | 旧缓存数据 + 更新中 | 暂时禁用 |

- 初次加载。
- 渐进加载。
- 空数据。
- 搜索无结果。
- 成功。
- 部分失败。
- 完全失败。
- 外部文件发生变化。
- 写入成功。
- 写入失败。

## 14. CLI / Desktop / Shared Core 边界

### 14.1 Shared Core

抽取并共用：

- 注册表读取、校验、迁移和原子写入。
- Project / Repository CRUD 领域规则。
- opener CRUD、解析和执行。
- Git 状态读取、扫描、fetch、安全推送判断与 Push。
- 状态文案所依赖的结构化数据，不共用终端 ANSI 展示。

### 14.2 CLI

- 保留全局命令 `project`。
- 保留交互模式和非交互子命令。
- npm 独立发布和更新。
- CLI presenter 继续输出终端表格和 ANSI 主题。

### 14.3 Desktop

- Electron 内置固定版本的 shared core。
- Vue 只通过 Electron IPC 调用受控能力，不直接访问 Node API。
- 不通过 `spawn('project')` 调用全局 CLI。
- 不注册或覆盖 shell 中的 `project` 命令。
- Desktop 源码版本独立于 npm 包版本，不提供官方应用更新器。

## 15. 实现前置与已发现缺口

以下事项在搭建页面前必须明确或修复：

1. `src/cli.js` 的单仓库 `push --fetch` 路径调用了 `fetchRepository`，但当前未从 `src/git.js` 导入；抽取 shared core 时需要修复并补测试。
2. 当前注册表保存是“临时文件 + rename”的原子替换，但尚无跨进程文件锁；CLI 与 Desktop 同时写入时仍可能后写覆盖先写。
3. Desktop 写入前需要比较文件版本或内容摘要；发现外部变更时停止写入并要求重新读取。
4. Schema 迁移前需要备份；当前 `schemaVersion` 只接受 `1`，尚无通用迁移管线。
5. 现有 `workspacePath`、`openTarget` 只在新增时写入；项目和代码库名称已有独立更新接口，但首版 UI 不承诺编辑路径类字段。
6. Git 状态当前每次实时调用 Git；Desktop 需要内存缓存、增量更新和页面切换复用，但不在注册表中持久化扫描结果。

## 16. 首版不包含

- Git commit、stage、stash、reset、rebase、merge、force push。
- 创建分支、切换分支、设置 upstream。
- Git 日志浏览器或完整 Git GUI。
- 代码编辑器、终端模拟器。
- GitHub Issue、Pull Request、Jira 等远端协作功能。
- 自动发现整块磁盘上的所有 Git 仓库。
- 删除或移动磁盘文件。
- 代码库跨项目移动，以及项目/代码库磁盘目录重命名。
- npm CLI 与 Desktop 互相安装或升级。
- 用户机器特定的内置 opener。
